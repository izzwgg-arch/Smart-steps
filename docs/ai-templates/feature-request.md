# Feature Request Template

Use for new behavior or new UI.

1. Read `CURSOR_START_HERE.md`.
2. Classify app and risk using `SAFE_CHANGE_ZONES.md`.
3. Load only relevant domain docs.
4. Write the intended flow:
   - page/component
   - API route
   - service
   - model
   - external integration
5. Check for existing patterns before adding new abstractions.
6. For high/extreme risk areas, ask for confirmation before implementation.
7. Update docs when behavior changes.

Never infer missing business rules. Use `UNKNOWN — verify before changing`.
